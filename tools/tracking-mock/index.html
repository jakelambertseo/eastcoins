Stat tracking plan

What the game records about players and the world today, the decisions it can't support yet, and a plan to record more without adding lag. The short version: the server already counts a lot per player (kills, gathers, crafts, xp per day, casino results) but almost nothing about where or how long, and nothing about where tickets come from. Nine additions cover the gaps. All of them are counters kept in memory and saved on the saves that already happen, plus one small world write a minute.

❓ Questions the game can't answer today

Each of these came up in a real decision this month and had to be guessed or worked around.

Are people camping the Wild without fighting?

No record of time on a map, or what anyone was doing there.

The Wilderness check had to infer it from kills
Where do tickets come from, and where do they go?

"Earned" is one lifetime number. Kills, selling to Bom, quests, dailies, events and the Tent all land in it together, and sinks (bills, the Store, fees) aren't counted at all.

The balance pass modelled income instead of measuring it
Which maps are dead, and which are crowded?

Only a live count of who's where right now; nothing kept.

The Yard crowding was judged by eye
What is killing people, and where?

A death count only. The server knows the killer and the map at the moment of death and throws both away.

Can't tell a hard boss from a bad spawn
Is a skill being trained, this week?

Per-skill xp exists only as weekly snapshots; the daily xp is all skills added together.

"Dead skill" calls were made from lifetime levels
Did that change work?

No before-and-after for anything that isn't a lifetime total: nothing per day by map, source or activity.

Every balance change so far is unmeasured
Are players coming back?

Lifetime play time and a session count, but no days played, so no retention or daily actives.

Launch week has no baseline
What sells, and what does the Exchange move?

No count of items sold to Bom; the Exchange keeps each item's last price but no volume.

Item values are set without demand data

📡 The nine additions

Each one says what it stores, where on the server it hooks in, and what it costs. "Free" means it rides saves that already happen and adds no writes; "tiny" adds to the one world write a minute. Click one for the details and a decision it would have settled.

⚡ Why none of this will lag

Lag in this game comes from three places: the 50 ms tick running long, too much sent to players, and storage writes piling up. The plan avoids all three by design.

The safety rules
  • One module (track.js), the way the weekly issue and world events are built. Every call into it is wrapped, so a bug in tracking can never break a kill, a sale or a save.
  • Counters only, no logs, except one capped list of the last 200 player kills. A counter can't grow with play time; a log can.
  • Capped maps: per character, only maps and items actually used get a key, and the daily ones keep 60 days like the xp-per-day record already does.
  • Nothing reads it during play. The hiscores, the wiki and the Weekly issue keep their own reads; the new data is for analysis, and optionally a keyed admin page later.
  • Tested the same way as the weekly issue: the real World on Node with the clock handed in, checking the counts and that nothing new is written per tick.

📊 How you'd use it

Straight away
  • Every balance or map write-up (like the Wilderness check) reads measured numbers from the nightly backup, the same way these two pages were built, with no new endpoint.
  • Before-and-after on any change: the day's tally is split by day, so "what changed after the Wild restock" is two weeks side by side.
  • The Weekly issue gains real sections: where people spent the week, the week's ticket sources and sinks, the deadliest monster, the busiest map.
Later, if you want it
  • A World dashboard tab in the admin panel: daily actives, minutes by map, tickets in and out, in the kit's style.
  • Player-facing "your week" on the profile: hours played, favourite map, tickets by source. It's the same numbers.
  • Alerts: a map nobody visited this week, a monster killing far more players than its level suggests, tickets minted jumping day over day.

🧭 Build order

One update. 1–4 first: they answer the questions on the table now (the Wild, the economy, deaths, maps). 5–9 are small additions in the same module. It needs a week of live data before the first measured write-up; the Wilderness changes can go in the same update, so that week covers them.
